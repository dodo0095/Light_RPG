## 1. 背景（30 秒版）

這是一個類 Habitica 的習慣養成 PWA，用日式 RPG 包裝，裝在 iPhone 主畫面使用。Sprint 1 只做**核心打卡循環**，沒有戰鬥畫面和美術。第一版沒有後端，資料全部存在 IndexedDB。目標使用者是老闆本人＋身邊少數人試用。

開工前必讀：

1. `CLAUDE.md`：特別是「本專案特有規則」6 條
2. `proposal/sprint1-proposal.md`：範圍、風險、失敗模式、驗收標準
3. `.knowledge/architecture.md`：目前的分層骨架（技術棧和目錄結構留空，等你補）
4. `晨光之誓_企劃書.md` 第 2、3、5、8 節

## 3. D1 技術棧評估條件（必須逐項回答）

| 條件 | 為什麼重要 |
|------|-----------|
| iOS Safari PWA 相容性（16.4+）、離線、加入主畫面 | 唯一目標平台 |
| 遊戲邏輯能寫成純函式並單元測試 | 換日和數值是高風險區 |
| Sprint 2 需求：像素動畫（Canvas）、逐字對話框、Web Audio 音效 | 不要選到 S2 得重寫的技術 |
| 以後能用 Capacitor 包成 iOS App | 企劃書 1.1 保留了上架彈性 |
| 第二版要接 Supabase 或 Django 同步 | 資料層不能綁死 |
| 部署：靜態站＋HTTPS，免費或低成本 | 試用階段 |
| Windows＋Git Bash 開發環境可用 | 工作區環境限制 |
| 維護成本：一人維護、bundle 體積 | 個人專案 |

## 4. D2 資料模型必須涵蓋

- 角色：職業、等級、經驗、四屬性經驗（體能／智慧／心靈／連結，財務可選）、HP、金幣、旅館狀態
- 任務：Habits（＋／－）、Dailies（頻率：平日／週末／自訂）、To-dos（檢查清單）、迷你版、難度、屬性、標籤
- 獎勵：自訂獎勵、價格
- 打卡紀錄：**事件式**（打卡、取消＝反向事件）
- 設定：換日時間（預設 04:00）、最後日結時間
- 內容資料（職業套組、預設習慣庫）與使用者資料分開存放
- 每筆資料預留 `id`（UUID）與 `updatedAt`，給第二版同步使用
- **預留但不實作**：Sprint 2 的 Boss 進度、章節、事件狀態、裝備（只要確認日後加入不必大改即可）
