## 1. 目標

做出一個裝在 iPhone 主畫面、離線可用的 PWA。開場選職業後，系統自動建好整套預設習慣，「今天」畫面可以打勾，打卡後會拿到金幣、經驗和扣血回饋。

本 Sprint **不做 RPG 視覺包裝**，只回答一個問題：**這套「點選而非設定」的上手方式加上打卡循環，能不能讓自己每天打開？**（RPG 包裝留到 Sprint 2）

目標使用者是自己＋身邊少數人試用（2026-10-23 決定）。

## 2. 範圍定義

### 做

| # | 功能/任務 | 優先級 | 說明 |
|---|----------|--------|------|
| 1 | PWA 外殼 | P0 | manifest、Service Worker 離線快取、iOS「加入主畫面」全螢幕可用 |
| 2 | 本機資料層 | P0 | IndexedDB 儲存角色、任務、紀錄；資料結構預留 Sprint 2 戰鬥／事件欄位與第二版同步欄位（id、updatedAt） |
| 3 | 換日（日結）機制 | P0 | 定義「一天」的分界（可設定換日時間，預設 04:00）；打開 App 時補算錯過的日結 |

| 5 | 「今天」單一畫面 | P0 | 今日 Dailies、Habits（＋／－）、To-dos 集中一頁，一鍵打勾，支援「迷你版也算完成」 |
| 6 | 數值循環 | P0 | 經驗／等級、四屬性經驗（主屬性 ×1.2）、金幣、HP；日結時未完成的 Dailies 扣血；HP 歸零的懲罰規則 |
| 7 | 旅館（暫停） | P0 | 入住後日結不扣血、Dailies 不計 |
| 8 | 預設內容庫 | P1 | 企劃書第 3 節全部內容，依屬性／類型分類，點「＋」一鍵加入 |
| 9 | 進階自由編輯 | P1 | 改名稱、難度、頻率（平日／週末／自訂）、檢查清單、屬性 |
| 10 | 自訂獎勵兌換 | P1 | 花金幣兌換現實獎勵（預設三項＋自訂） |
| 11 | 資料匯出／匯入 | P1 | JSON 備份，防止 iOS 清除網站資料 |
| 12 | 快速新增（規則判斷） | P2 | 輸入文字，以關鍵字規則判斷類型與屬性；時間不夠就砍 |

- 第一人稱戰鬥畫面、Boss、章節、劇情對話（Sprint 2）

- 隨機事件與資料包（Sprint 2）
- 推播通知（Sprint 2；iOS 需另外處理 Web Push 權限）
- 轉職系統、帳號、雲端同步、組隊（第二版）
- 正式美術、音效、像素字型（介面先用簡單的藍色視窗風 CSS 撐場）

## 5. 風險評估

| 風險 | 可能性 | 影響 | 緩解措施 |
|------|--------|------|---------|
| iOS Safari 清除 IndexedDB 資料 | 中 | 高 | 引導加入主畫面（安裝後的 PWA 較不會被清）＋ JSON 匯出匯入（#11） |
| 數值不平衡（扣血太重或太輕） | 高 | 中 | 數值集中在一個設定檔，試用期間可直接調整 |
| 範圍蔓延到 RPG 視覺 | 中 | 中 | 第 2 節明確排除；視覺需求一律記到 Sprint 2 backlog |
| 時區／換日邊界錯誤 | 中 | 高 | 換日邏輯獨立模組＋單元測試（跨午夜、多日未開、旅館期間） |
| 沒有 RPG 包裝，自用動機不足 | 中 | 中 | 本 Sprint 就是在驗證這點；試用數據作為 Sprint 2 優先級依據 |

## 6. 失敗模式分析

| 失敗場景 | 可能性 | 影響 | 偵測方式 | 緩解措施 |
|---------|--------|------|---------|---------|
| 多天沒開 App，再打開時一次扣光 HP | 中 | 高 | 單元測試：模擬 7 天未開 | 補算日結設上限（例：最多扣 3 天），規則寫進決策表 |
| Service Worker 快取舊版，更新不生效 | 高 | 中 | 部署後實機確認版本號 | SW 版本號＋「有新版本，點此更新」提示 |
| 打勾後取消，金幣／經驗沒有回滾 | 中 | 中 | 單元測試 | 打卡紀錄採事件式，取消即反向事件 |
| 匯入壞掉的 JSON 覆蓋資料 | 低 | 高 | 匯入前檢查格式 | 匯入前自動備份一份 |

## 7. 可觀測性

- **日誌策略**: 本機事件紀錄（打卡、日結、扣血），可在設定頁查看最近 50 筆，方便除錯數值
- **關鍵 Dashboard**: 不建置；試用指標由 experiment-tracker 用匯出的 JSON 統計
- **告警規則**: 不適用（無後端）

## 8. Rollback 計畫

| 項目 | 說明 |
|------|------|
| 程式碼回滾 | git revert 後重新部署靜態站 |
| DB 回滾 | 資料結構帶 schemaVersion，遷移前自動匯出備份 |
| 判斷標準 | 打卡或日結造成資料遺失／錯誤 |
| 負責人 | project-shipper（部署）、tech-lead（程式碼） |

## 9. 驗收標準

- [ ] iPhone Safari 加入主畫面後全螢幕開啟，飛航模式下可正常打卡
- [ ] 從安裝到完成第一次打卡 ≤ 60 秒（含選職業）

- [ ] Dailies／Habits／To-dos 打勾、取消，金幣／經驗／屬性經驗正確增減
- [ ] 日結：未完成 Dailies 正確扣血；旅館期間不扣血；多日未開補算符合決策表
- [ ] 預設庫一鍵加入、進階編輯可用
- [ ] 匯出 → 清除資料 → 匯入後狀態完全還原
- [ ] 換日與數值邏輯單元測試全數通過
- [ ] **試用目標**：老闆本人連續使用 14 天，打開率與完成率由 experiment-tracker 回報，作為 Sprint 2 決策依據
- [ ] 勾選的所有關卡皆通過
